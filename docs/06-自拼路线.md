# 自拼路线（2026-11-13 定）

> 不借 Sunshine 整机，也不换方向。用宽松许可的轮子自己拼，主机端全部自己掌控。
> 原因不在技术，在项目初衷：自己的画面不经过别人的服务器。

---

## 一、分工

| 范围 | 谁做 | 说明 |
|---|---|---|
| 局域网传输 | 我们 | 裸 UDP、自定义分片、NACK 重传，已通 |
| 主机端采集/编码/输入 | 我们 | 本轮重点 |
| 客户端 UI（Godot） | 我们 | 项目真正的价值所在 |
| 公网 / 跨网 | 朋友 | 他说他来处理，我们不实现 |

**边界纪律**：传输抽象仍然切在「编码后的帧」，不切在包。
只要这条不变，朋友那边接的是 WebRTC、自建隧道、还是 Tailscale 这类虚拟组网，核心都不用改。

顺带一个便宜的好处：如果他用虚拟组网把两台机器拉进同一个网段，我们的内网模式**直接就能跨公网跑**，
一行打洞代码都不用写。我们的 MTU 取 1200（包头 32），虚拟网卡常见的 1280 MTU 也塞得下。

## 二、编码后端：三层可插拔

不能写死 NVENC。朋友的 AMD 核显也得能用。

```
trait VideoEncoder {
    fn feed(&mut self, frame: InputFrame, pts_us: i64) -> Result<Vec<EncodedFrame>>;
    fn request_keyframe(&mut self);
    fn backend(&self) -> Backend;
}
```

| 层 | 实现 | 延迟量级 | 谁用 |
|---|---|---|---|
| 最优 | NVENC 直连（D3D11 纹理零拷贝） | 3~5 ms | N 卡 |
| 次优 | AMF 直连 / QSV 直连 | 5~10 ms | A 卡 / I 卡 |
| 兜底 | Media Foundation 硬件 MFT | ~25 ms | 全部，且保证能跑 |

先做「最优 + 兜底」两档：N 卡走直连，其他走 MF 硬件 MFT，朋友当天就能用。
AMF / QSV 直连等有真实需求再补，接口先留好。

## 三、五件事（按收益排序）

1. **NVENC 直连。** 现在 37ms 里有 25ms 是 MF 异步 MFT 的排队。NVENC 的 `nvEncodeAPI` 十来个函数，
   直接吃 D3D11 纹理，不落 CPU。预计整链路进 15ms 上下。
2. **采集线程化。** `AcquireNextFrame` 在锁屏/切桌面/显示器休眠时会挂死不返回，超时参数无效。
   挪到独立线程，最坏是采集线程死掉、主循环还活着能重建，而不是整个进程僵住。
   （当前对策：锁屏前先探 `OpenInputDesktop`，卡死 3 秒自杀重启。属于补丁，线程化才是正解。）
3. **输入注入。** SendInput 绝对坐标、多显示器负坐标映射、键盘扫描码、DPI 感知。
   没有这块它永远是个播放器。
4. **客户端显示换 D3D11 SwapChain。** GDI StretchDIBits 又糊又慢（1080p 拉伸 3ms），
   而且和显示器 vsync 对不齐。
5. **安卓端硬解上屏。** MediaCodec + SurfaceView，环境已就绪。

## 四、已经踩过的坑（别再踩）

- `D3D11CreateDevice` 传了适配器就必须用 `D3D_DRIVER_TYPE_UNKNOWN`，传 HARDWARE 直接 E_INVALIDARG。
- 硬件 MFT 不实现 `IMFAttributes`，QI 返回 `E_NOINTERFACE`；属性存储要走 `IMFTransform::GetAttributes()`。
- 异步 MFT 不要「等事件再喂帧」，对面不发事件就死锁；直接喂，忙就丢一帧。
- D3D11 感知的 MFT 必须 `MFT_MESSAGE_SET_D3D_MANAGER`，且输入必须是纹理，否则 `E_UNEXPECTED`。
- 硬件编码器的输出纹理至少三张轮转，一张边写边读会抽黑帧。
- 解码器输出是宏块对齐的（1080 → 1088），缓冲区按 coded 尺寸算，可见尺寸看 `MF_MT_MINIMUM_DISPLAY_APERTURE`。
- GDI 显示必须双缓冲 + 处理 `WM_ERASEBKGND`，否则闪黑。
- 软件 H.264 编码器（MS 那个）有 560ms 固有时延，不能当兜底，只能当最后手段。
